Você é um engenheiro sênior de IA, visão computacional, processamento de áudio e edição automatizada de vídeo.

Sua missão é criar um sistema Python LOCAL chamado:

# L.D.PORTO VIDEO ANALYZER

Este sistema será a primeira etapa de uma futura plataforma semelhante ao OpusClip.

IMPORTANTE:

Nesta etapa NÃO devemos gerar cortes finais, Shorts, Reels ou TikToks.

O objetivo desta primeira aplicação é ANALISAR COMPLETAMENTE um vídeo original e produzir uma representação estruturada extremamente detalhada do conteúdo.

O resultado será posteriormente entregue a outro agente/LLM, que escolherá os melhores cortes.

Portanto:

ANALISAR PRIMEIRO.
EDITAR DEPOIS.

---

# 1. OBJETIVO PRINCIPAL

Dado um vídeo:

input/video.mp4

o sistema deverá compreender:

- tudo que foi falado;
- quando cada palavra foi falada;
- quem está falando;
- quais pessoas aparecem;
- onde cada pessoa está localizada no frame;
- qual pessoa provavelmente corresponde ao locutor atual;
- quando duas ou mais pessoas aparecem simultaneamente;
- quando duas pessoas participam ativamente de uma conversa;
- mudanças de câmera;
- mudanças de cena;
- mudanças de assunto;
- textos visíveis;
- perguntas;
- respostas;
- frases impactantes;
- momentos emocionais;
- momentos engraçados;
- declarações controversas;
- informação importante;
- possíveis hooks;
- possíveis conclusões;
- trechos que fazem sentido isoladamente;
- trechos que dependem demais do contexto anterior;
- silêncios;
- pausas;
- interrupções;
- sobreposição de fala;
- risadas;
- música;
- ruído;
- qualidade do áudio;
- qualidade visual.

O Analyzer deve gerar um MAPA TEMPORAL COMPLETO do vídeo.

---

# 2. PRINCÍPIO FUNDAMENTAL

O sistema NÃO deve tentar criar Shorts imediatamente.

Primeiro deve responder:

"O que acontece neste vídeo inteiro?"

Depois:

"Quem participa?"

Depois:

"Quem fala em cada momento?"

Depois:

"Onde essa pessoa está na imagem?"

Depois:

"Quais momentos possuem potencial editorial?"

Somente um segundo programa utilizará essas informações para renderizar os vídeos.

---

# 3. PIPELINE PRINCIPAL

Implementar o processamento aproximadamente nesta ordem:

1. inspeção do arquivo;
2. extração do áudio;
3. normalização temporária do áudio;
4. transcrição;
5. timestamps por palavra;
6. diarização dos locutores;
7. alinhamento transcript + speaker;
8. detecção de cenas;
9. detecção de rostos/pessoas;
10. tracking das pessoas;
11. associação entre pessoa visível e locutor;
12. análise da posição das pessoas;
13. detecção de texto/OCR quando relevante;
14. análise semântica;
15. segmentação por assunto;
16. identificação de momentos editoriais;
17. geração dos arquivos estruturados;
18. relatório final.

---

# 4. TRANSCRIÇÃO

A transcrição é prioridade absoluta.

Idioma principal:

Português brasileiro.

O sistema deve produzir uma transcrição o mais fiel possível ao áudio.

NÃO:

- resumir falas;
- corrigir conteúdo;
- reescrever frases;
- inventar palavras;
- transformar fala informal em português formal.

Preservar:

- gírias;
- repetições;
- hesitações relevantes;
- nomes;
- palavrões;
- expressões regionais;
- frases incompletas quando realmente ocorrerem.

Cada palavra precisa possuir:

- texto;
- timestamp inicial;
- timestamp final;
- confidence;
- speaker;
- segment_id.

Exemplo:

{
  "word": "cirurgia",
  "start": 23.421,
  "end": 23.910,
  "confidence": 0.982,
  "speaker": "SPEAKER_01",
  "segment_id": "SEG_00034"
}

Não arredondar excessivamente os timestamps.

---

# 5. PALAVRAS DE BAIXA CONFIANÇA

Palavras com baixa confiança devem ser marcadas.

Exemplo:

"needs_review": true

Não substituir automaticamente uma palavra duvidosa por uma palavra inventada.

Adicionar uma lista:

low_confidence_words

contendo:

- palavra;
- timestamp;
- confidence;
- contexto anterior;
- contexto posterior.

---

# 6. DIARIZAÇÃO DE LOCUTORES

Identificar os diferentes locutores como:

SPEAKER_00
SPEAKER_01
SPEAKER_02
...

Não inventar nomes reais.

Registrar:

- início da fala;
- fim;
- speaker;
- confiança quando disponível;
- overlap de fala.

Exemplo:

{
  "start": 21.4,
  "end": 29.8,
  "speaker": "SPEAKER_01",
  "overlap": false
}

---

# 7. PESSOAS VISÍVEIS

Detectar pessoas/rostos presentes no vídeo.

Criar identidades persistentes:

PERSON_001
PERSON_002
PERSON_003
...

A mesma pessoa aparecendo novamente deverá, sempre que tecnicamente possível, manter o mesmo PERSON_ID.

Não tentar identificar automaticamente celebridades ou descobrir identidade civil pela aparência.

O sistema pode posteriormente associar nome somente se houver evidência textual explícita no próprio vídeo, transcrição ou metadados fornecidos.

---

# 8. TRACKING

Para cada pessoa visível registrar ao longo do tempo:

- PERSON_ID;
- frame/time;
- bounding box;
- centro X;
- centro Y;
- largura;
- altura;
- percentual aproximado do frame ocupado;
- face_visible;
- body_visible;
- tracking_confidence.

Bounding boxes devem preferencialmente utilizar valores normalizados entre 0 e 1.

Exemplo:

{
  "person_id": "PERSON_001",
  "time": 27.42,
  "bbox": {
    "x": 0.12,
    "y": 0.08,
    "width": 0.48,
    "height": 0.84
  },
  "center": {
    "x": 0.36,
    "y": 0.50
  }
}

---

# 9. QUEM ESTÁ FALANDO?

Este é um dos pontos mais importantes do sistema.

O Analyzer deverá tentar associar:

SPEAKER_XX

com

PERSON_XXX

por intervalo temporal.

Usar sinais disponíveis como:

- presença da pessoa;
- movimento labial;
- atividade facial;
- posição;
- continuidade temporal;
- mudança de câmera;
- diarização;
- active speaker detection.

Gerar algo como:

{
  "start": 23.0,
  "end": 31.5,
  "speaker": "SPEAKER_01",
  "visible_person": "PERSON_003",
  "association_confidence": 0.91
}

Se não houver confiança suficiente:

"visible_person": null

Nunca inventar associação.

---

# 10. ACTIVE SPEAKER

Em cada intervalo relevante determinar:

- quem está falando;
- se essa pessoa está visível;
- se existe apenas uma pessoa;
- se existem múltiplas;
- qual delas deve receber foco editorial.

Exemplo:

{
  "time": 42.5,
  "active_speaker": "SPEAKER_02",
  "active_person": "PERSON_004",
  "visible_people": [
    "PERSON_004",
    "PERSON_006"
  ]
}

---

# 11. COMPOSIÇÃO VISUAL

Para cada segmento registrar uma recomendação visual.

Possíveis valores:

single_focus
speaker_follow
two_person_scene
split_screen_candidate
wide_scene
group_scene
object_focus
screen_content
unknown

IMPORTANTE:

NÃO executar crop.

NÃO renderizar split screen.

Somente recomendar o layout que o futuro editor poderá utilizar.

---

# 12. DUAS PESSOAS CONVERSANDO

Quando duas pessoas estiverem participando ativamente de uma conversa, avaliar:

- ambas aparecem simultaneamente?
- aparecem em câmeras diferentes?
- há alternância frequente?
- há fala sobreposta?
- uma pessoa reage visualmente enquanto a outra fala?
- vale preservar ambas no frame?

Se fizer sentido registrar:

"recommended_layout": "split_screen_candidate"

Também registrar:

"primary_person"
"secondary_person"

Exemplo:

{
  "start": 55.2,
  "end": 67.8,
  "primary_person": "PERSON_001",
  "secondary_person": "PERSON_002",
  "recommended_layout": "split_screen_candidate",
  "reason": "conversation between two visually active participants"
}

O processamento visual definitivo será realizado pelo segundo programa.

---

# 13. PESSOA PRINCIPAL

Para cada trecho definir:

primary_person

com base principalmente em QUEM ESTÁ FALANDO.

A pessoa principal NÃO deve ser escolhida apenas porque é maior ou está centralizada.

Ordem de prioridade:

1. pessoa falando;
2. pessoa diretamente relacionada à fala;
3. pessoa reagindo;
4. pessoa visualmente dominante;
5. composição original.

---

# 14. ROSTO E REGIÃO DE SEGURANÇA

Para cada pessoa:

- bbox;
- face_bbox;
- eyes_position quando disponível;
- head_center;
- body_center;
- distance_to_left;
- distance_to_right;
- safe_crop_possible;
- estimated_vertical_crop.

Não executar o crop ainda.

# 16. SHOT CHANGE VS CONTENT CHANGE

Não confundir:

mudança de assunto.

Registrar separadamente:

visual_scene_change

Uma entrevista pode trocar de câmera 20 vezes dentro do mesmo assunto.

# 47. SEM ALUCINAÇÕES

Regra essencial:

O sistema deve distinguir:

OBSERVAÇÃO

de

INFERÊNCIA.

Exemplo:

observação:
PERSON_001 está visível.

inferência:
PERSON_001 provavelmente corresponde a SPEAKER_02.

Adicionar confidence para inferências.

Não tratar inferência incerta como fato.

---

# 48. NÃO IDENTIFICAR PESSOAS SEM EVIDÊNCIA

Não afirmar:

"Esta pessoa é Fulano"

apenas por reconhecimento facial.

até que exista evidência explícita fornecida pelo vídeo, metadados ou usuário.

# 61. PREPARAÇÃO DE ÁUDIO PARA TRANSCRIÇÃO

Antes da transcrição, o sistema deve criar diferentes representações do áudio.

NUNCA modificar ou sobrescrever o áudio original.

Gerar:

audio/original.wav
audio/speech_clean.wav
audio/speech_isolated.wav quando necessário

O objetivo é obter a MELHOR transcrição possível sem destruir informações importantes do áudio.

---

## 61.1 ÁUDIO ORIGINAL

Extrair do vídeo uma cópia lossless ou de alta qualidade.

Este áudio será a referência principal para:

- sincronização;
- diarização;
- detecção de speakers;
- overlap de fala;
- eventos de áudio;
- análise posterior;
- validação da transcrição.

Nunca descartar esta trilha.

---

## 61.2 SPEECH CLEAN

Criar uma versão otimizada especificamente para reconhecimento de fala.

Aplicar de forma conservadora:

- normalização;
- remoção de DC offset quando necessária;
- redução de ruído;
- redução de hum;
- high-pass leve para ruídos graves;
- redução de reverberação quando tecnicamente segura;
- controle de volume;
- speech enhancement.

Não aplicar processamento exagerado que possa destruir:

- consoantes;
- sibilância;
- respiração;
- finais de palavras;
- vozes mais graves;
- vozes mais agudas.

speech_clean.wav deverá ser a fonte preferencial para ASR quando apresentar melhor qualidade.

---

# 62. DETECÇÃO DE MÚSICA SOB A FALA

Analisar se existe:

- instrumental;
- background music;
- trilha;
- vinheta;
- música alta cobrindo locução.

Registrar:

music_under_speech: true/false

music_level_relative_to_speech

Quando música interferir significativamente na inteligibilidade, criar uma trilha adicional:

audio/speech_isolated.wav

---

# 63. SEPARAÇÃO DE VOZ / INSTRUMENTAL

Quando necessário utilizar source separation para reduzir:

- instrumental;
- música de fundo;
- efeitos musicais.

O objetivo NÃO é produzir um vocal musical perfeito.

O objetivo é facilitar o reconhecimento das PALAVRAS.

A separação deve preservar o máximo possível:

- consoantes;
- sílabas;
- transientes de voz;
- inteligibilidade.

Não usar automaticamente speech_isolated para todas as situações.

Source separation pode introduzir artefatos.

---

# 64. ESTRATÉGIA ADAPTATIVA DE TRANSCRIÇÃO

O sistema poderá possuir até três fontes:

ORIGINAL
SPEECH_CLEAN
SPEECH_ISOLATED

Escolher automaticamente a melhor fonte para ASR.

Regra preferencial:

fala limpa + pouco ruído
→ SPEECH_CLEAN

fala com música significativa
→ comparar SPEECH_CLEAN e SPEECH_ISOLATED

se source separation gerar artefatos
→ utilizar SPEECH_CLEAN ou ORIGINAL

Nunca presumir que uma voz isolada é automaticamente melhor.

---

# 65. TRANSCRIÇÃO MULTIPASS

Para trechos difíceis, permitir executar reconhecimento em mais de uma versão do áudio.

Exemplo:

PASS 1:
speech_clean.wav

PASS 2:
speech_isolated.wav

Somente para regiões nas quais:

- confidence seja baixo;
- exista música forte;
- exista ruído;
- existam palavras incompreensíveis;
- o primeiro reconhecimento esteja inconsistente.

Comparar resultados.

Não fazer múltiplos passes no vídeo inteiro desnecessariamente.

---

# 66. CONSENSO DE TRANSCRIÇÃO

Quando dois passes produzirem resultados diferentes, comparar:

- confidence por palavra;
- contexto linguístico;
- alinhamento temporal;
- consistência com palavras próximas;
- qualidade estimada da fonte de áudio.

Não substituir palavras simplesmente porque uma segunda hipótese "parece melhor".

Registrar alternativas quando houver incerteza.

Exemplo:

{
  "start": 34.82,
  "end": 35.41,
  "selected": "cirurgia",
  "alternatives": [
    {
      "text": "cirurgia",
      "source": "speech_clean",
      "confidence": 0.94
    },
    {
      "text": "cirúrgica",
      "source": "speech_isolated",
      "confidence": 0.61
    }
  ]
}

---

# 67. QUALIDADE POR TRECHO

Calcular aproximadamente para cada intervalo:

speech_quality
background_music_level
background_noise_level
speech_to_background_ratio
transcription_difficulty

Isso permitirá direcionar processamento adicional somente aos trechos difíceis.

---

# 68. NÃO USAR VOZ ISOLADA PARA TUDO

IMPORTANTE:

A versão com instrumental removido é uma ferramenta auxiliar para transcrição.

Ela NÃO deverá substituir o áudio original para:

- diarização definitiva;
- análise de overlap;
- reconhecimento de locutores;
- sincronização audiovisual;
- active speaker detection;
- renderização futura.

Para essas tarefas, utilizar:

original.wav

ou

uma versão levemente tratada.
